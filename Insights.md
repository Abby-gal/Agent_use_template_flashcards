## Step 1 — Planning the app

### What was new to me

Turning my project idea into numbered features and writing a browser check for each one.

### New things I did learn

A concrete acceptance criterion helps me tell whether a feature works. For example, entering 2 actual exercise hours with a 4-hour goal should show 50%.

## Step 2 — Building the planner with Copilot

### What was new to me

Using `localStorage` to remember information after a page reload.

### New things I did learn

Saving values and showing them again are two separate steps. The planner has to read the saved weekly targets when the page loads and put them back into the fields.
Planned and actual times need to be stored separately so I can compare them and copy the planned times when an activity goes as expected.

## Step 3 — Testing and improving the layout

### What was new to me

Seeing how adding real activities exposed layout problems I missed when the timetable was empty.

### New things I did learn

Wider day columns make the full times readable. Horizontal scrolling keeps the rest of the page usable when all seven days cannot fit.
Asking Copilot for one change at a time made it easier to check the result in the browser before moving on.
